# 階段 8 · 替代準備（網頁版數據匯入）

日期：2026-11-26。目標：Laurent 拍板替代時，網頁版的本機數據一次搬進原生版（規格書 §5 第 8 步的原生側；網頁版導出功能母本已內建，不需改母本）。

## 一、搬遷流程（用戶視角）

1. 網頁版：設定 → 數據備份 → 「導出備份」（複製一段 JSON；或經匯入框取得全文存成 .json 檔）。
2. 把 JSON 檔送進 iPhone（AirDrop／檔案／微信傳檔皆可）。
3. 原生版入口（二選一）：設定 → 系統設定 → 數據備份 → 「選擇備份文件」；或在檔案 App 對該 .json 以本 App 開啟／分享入。
4. 確認 sheet 預覽將匯入的段、未映射項與注意事項 → 「確認匯入」即完成（取消零副作用）。

## 二、信封格式（母本實查）

`buildBackupJson`（index.html 行 11780）：`{app: "LAURENT-Acoustic-Reference", v: 1, profile, settings}`；profile＝`laurent_profile_v7` 物件（createDefaultProfile 行 6211），settings＝`laurent_settings_v6` 物件（saveAppSettings 行 8101）。背景圖過大時母本清空 settings.customBgDataUrl 並標 `bgOmitted: true`。母本自身的匯入驗證口徑（app 標記符＋至少一段存在）原生匯入器同構沿用。

## 四、衝突策略與失敗回退

- **段級整段替換**：profile 段出現 → 其收藏／自訂樂器／用戶預置／節拍器預設整段以備份為準；settings 段同理逐欄覆寫。未出現的段一律保留現有值。
- **欄位級寬容**：單欄壞值（型別漂移／枚舉不識別）只跳過該欄並在確認 sheet 記警告，不整份拒絕；自訂樂器／預置壞筆整筆跳過並計數。
- **信封級拒絕**：非 JSON（notJSON）、app 標記不符（wrongApp）、兩段皆缺（emptyEnvelope）→ 錯誤提示，store 零寫入。
- **原子性**：plan 在組裝期完成全部解析與健全化；applyImport 是確認後的純賦值序列，組裝失敗不可能寫入半套數據。取消確認 = pendingImportPlan 清空，零副作用。
