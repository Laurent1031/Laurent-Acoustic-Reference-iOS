## 根因 1：persist() 全量編碼風暴 → 語言與一切設定「沒反應／反應很慢」（本批 A，已修）

- AppStore 共 19 個 @Published 屬性以 `didSet { persist() }` 落盤；persist() 每次把**整個狀態** JSON 編碼＋原子寫盤，其中 `customBgData`（用戶自訂背景照片，MB 級）以 base64 內嵌——每次任一設定變更（切語言、拖玻璃不透明度、切主題、點收藏、調 A4……）都在主線程付出百毫秒級編碼＋寫盤。
- 語言切換的接線本身經代碼核查無誤：Picker 綁 $store.language → ContentView onChange 同步 L10n → 觀察 store 的視圖重繪查表。卡頓來自 persist 風暴＋（批 2 架構下）整頁重繪，疊加發熱降頻，實機表現即「沒用／很慢／只有某頁有反應」（後開的頁面以新語言首繪，先開的頁面重繪被拖延）。
- 修法（AppStore.swift）：
  - 背景圖分檔 `AcousticReference/custom-bg.bin`：state JSON 不再內嵌圖檔（恆寫 nil），回到 KB 級；圖檔僅自身變更時寫入／刪除；舊版內嵌值載入沿用、首輪 persist 自動遷移（先寫分檔、後寫新 JSON，崩潰不丟圖）。
  - 冪等守衛：編碼結果與上次已寫盤相同則跳過寫入。
  - 備份匯入／匯出走 store.customBgData 屬性（記憶體真源），不受存檔格式變更影響，已核對 BackupImporter 兩處接線。

## 根因 2：收藏列獨佔手勢吞捲動（本批 B，已修）

- 收藏晶片以獨佔 `.gesture()` 掛「長按 200ms → 拖曳」序列。SwiftUI 仲裁下 ScrollView 須等此手勢失敗才捲動：快速滑動尚可，慢速拖動時長按先成立、拖曳把捲動整個吃掉——即「滑不了」；列尾晶片與「＋ 常用」到不了，即「有幾個按不到」。
- 修法（TunerView.swift）：改 `.simultaneousGesture`（快速滑動長按自動落空、捲動即時跟手）；favoritesRow 的 ScrollView 加 `.scrollDisabled(favDragId != nil)`，拾起排序後鎖捲動專心拖曳。

## 全域手勢／捲動衝突審計（本批 C）

全倉 `.gesture`／`.highPriorityGesture` 掛載點逐一核查：

| 位置 | 所在容器 | 結論 |
|---|---|---|
| TunerView 收藏晶片 favDragGesture | 橫向 ScrollView 內 | **本批已修**（根因 2） |
| TunerView 目標晶片列 targetStrip | 橫向 ScrollView | 批 2 已用 simultaneousGesture＋glide 旗標，無衝突 |
| TunerView 純律主音列 | 橫向 ScrollView | 純 Button，無手勢衝突 |
| InstrumentLibraryView 分類列 | 橫向 ScrollView | 純 Button，無衝突 |
| MetronomeView dialDrag／numberDrag | 定高頁（無 ScrollView） | 無衝突 |
| MetronomeView faderDrag（highPriority） | 定高頁 | 無衝突 |
| GlassSegmentedControl segDrag（TunerTheme） | 設定 sheet 的 ScrollView 內亦有使用 | 已知取捨：分段控件本體為橫拖控件，在其上起手**垂直**捲動會被吃掉；sheet 其餘面積充足可起手捲動。改並行手勢有誤切段位風險，本批不動、記錄在案 |

設定兩頁（PreferencesView／SystemSettingsView）與樂器庫均有 ScrollView 包裹，無「整頁滑不了」結構問題。
